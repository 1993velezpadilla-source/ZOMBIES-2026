# IW3 Android phase IE — GLES3 program compilation boundary (NOT GAME)

Date: 2026-11-02. PR #4; branch `feature/iw3-native-android-arm64-20261025`.

## Baseline and blocker
The prior shader source pair generated by original IW3 D3D9 token translators had no real GLES3 shader compilation or program linking. GitHub Actions run 41553282716 has successful original-renderer compile-probe jobs, but does not prove a real map frame or playable APK.

## Implementation
Added `third_party/KisakCOD/src/gfx_d3d/r_android_gl_program.{h,cpp}`. This accepts the previously translated original vs_3_0 / ps_3_0 source strings, invokes real GLES3 glCreateShader/glShaderSource/glCompileShader and glCreateProgram/glAttachShader/glLinkProgram, checks compile/link status, captures driver logs, releases intermediate shaders, checks POSITION0 and COLOR0 attribute locations (0,1), and provides explicit program destruction. Failures release GL objects. No fallback geometry, engine or placeholder shaders are introduced.

Added `.github/workflows/iw3-gles3-program-gate.yml` for a host GLES3-header syntax compile with `__ANDROID__` enabled. This is **not** a runtime GPU test or ARM64 compile; at the time of this record, no successful run of the new workflow has been verified.

## Limitations / next gate
This provider is intentionally not yet wired into original `r_material.cpp` and `rb_shade.cpp`, and has no real EGL context, material shader selection, VAO, texture/sampler bindings, original map draw, or gameplay. A real GLES3 context test must translate genuine resource shaders and compile/link them on GPU before binding into the original material pipeline. Host compilation alone cannot establish runtime success.

`IW3_PLAYABLE_APK=false`. JNI diagnostic is not gameplay. Keep PR open and unmerged.
